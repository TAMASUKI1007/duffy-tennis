# 予約支援 運用手順

サイトで受け付けるのは **仮予約** です。予約の確定は **InstagramのDMで運営者が行います**（LINE公式は運用開始まで使いません。2026-10-15 変更）。
システムが自動で予約を確定したり、カレンダーに書き込んだりすることはありません。

---

## 1. 受付時間を変える

編集するのは **`apply.html` の1か所だけ**です。ファイルを開いて `BOOKING_CONFIG` を探してください
（ファイルの後半、`<script>` の先頭にあります）。

```js
const BOOKING_CONFIG = {
  // 基本ルール：日曜午前・月曜午前・水曜終日は受付しない
  hours: {
    sun: { from: '12:00', to: '20:00' },  // 午前は受付なし
    mon: { from: '12:00', to: '20:00' },  // 午前は受付なし
    tue: { from: '12:00', to: '20:00' },
    wed: null,                            // 終日受付なし
    thu: null,                            // 木曜は受付なし
    fri: { from: '13:00', to: '16:00' },
    sat: { from: '12:00', to: '20:00' }
  },
  ...
};
```

現在の基本ルールは **日曜午前・月曜午前・水曜終日は受付しない** です（2026-10-14 設定）。
「午前だけ止める」は `from` を `'12:00'` にする、「終日止める」は `null` にする、で表せます。

### 書き方

- 曜日のキーは **英語3文字**：`sun` 日 / `mon` 月 / `tue` 火 / `wed` 水 / `thu` 木 / `fri` 金 / `sat` 土
- 時刻は `'8:00'` や `'12:30'` のように **シングルクォートで囲む**
- **受付をしない曜日は `null`** と書く（`thu: null` のように）

### 表示される開始時刻

レッスンは2時間なので、**受付終了時刻の2時間前が最後の開始時刻**になります。30分刻みです。

| 設定 | 表示される開始時刻 |
|---|---|
| `{ from: '8:00', to: '12:00' }` | 8:00 / 8:30 / 9:00 / 9:30 / **10:00**（12:00終了） |
| `{ from: '13:00', to: '16:00' }` | 13:00 / 13:30 / **14:00**（16:00終了） |
| `{ from: '12:00', to: '20:00' }` | 12:00 〜 **18:00**（20:00終了）の13枠 |
| `null` | その曜日は選べない（カレンダーに「-」） |

受付終了を過ぎて終わる時間は自動的に出ません。**「16:00まで」と書けば、レッスンが16:00を超えることはありません。**

## 2. お休みの日を追加する（大会・私用など）

同じ `BOOKING_CONFIG` の `blockedDates` に、`'YYYY-MM-DD'` の形式で足してください。

```js
  // 受付を止める日（'YYYY-MM-DD'）。初期値は空です。
  blockedDates: ['2026-10-10', '2026-10-11', '2026-12-29'],
```

- カレンダー上でその日がグレーになり、**選べなくなります**
- 日付の下に「休み」と表示されます
- 終わったら行から消せば元に戻ります

> ⚠️ 年をまたぐときは年の書き間違いにご注意ください。`2026-01-03` と `2027-01-03` は別の日です。

## 3. 曜日ごとに開催コートが決まっている場合

現在は固定コートなし（`fixedCourts: {}`、2026-10-27 に金曜の固定をやめました）。固定したい曜日があれば次のように書きます。

```js
  fixedCourts: {
    fri: '〇〇テニスプラザ'
  },
```

その曜日の日時を選ぶと、

- **希望コートの入力欄とコート予約代行のチェックが消えます**
- 「開催コート：〇〇テニスプラザ」と自動で表示され、申込内容にもそのまま入ります

お客さんが別の曜日に変更すると、自動で入れたコート名は消え、入力欄が戻ります。
**お客さんが自分で入力したコート名は消えません。**

コートを追加・変更するときは行を足すだけです。

```js
  fixedCourts: {
    fri: '〇〇テニスプラザ',
    sat: '〇〇市民コート'
  },
```

固定をやめる場合は `fixedCourts: {}` にしてください。

## 4. 変更したあとにすること（公開のしかた）

公開先は **Cloudflare Pages**（https://duffy-tennis.pages.dev/）です（2026-10-26 に Vercel から移行）。

1. 変更を保存して、GitHub に push する（履歴のため）
2. ターミナルで次を実行する。テスト → `dist/` を作る → Cloudflare にアップロード、まで一度に走ります

   ```
   npm run deploy
   ```

   初回だけ `npx wrangler login` でブラウザからCloudflareにログインしてください（daiiki3368@gmail.com のアカウント）。
3. 1分ほどで https://duffy-tennis.pages.dev/ に反映されます。変えた曜日の日付をタップし、**表示される開始時刻が想定どおりか**を確認する

公開されるファイルは `scripts/build.mjs` の `PUBLISH` に書いたものだけです（`db/` `docs/` `tests/` は出ません）。
Vercel 側は `vercel.json` で全ページを Cloudflare へ恒久転送（301）しており、公開は止まっています（2026-10-27）。古いリンクを踏んでも新しいサイトに飛びます。

設定の書式を間違えると（カンマ忘れ・クォート忘れなど）、**申込フォーム全体が表示されなくなります。**
変更後は必ず実際の画面で確認してください。

## 5. 申込が入ってからの流れ

```
お客さんが申込フォームを送信
   ↓
  ① Supabase に保存される
  ② EmailJS で運営者とお客さんにメールが届く
   ↓
完了画面に「仮予約を受け付けました。予約はまだ確定していません。」と表示
   ↓
お客さんが「InstagramでDMを送る」ボタンから @duffy_tennis にDMを一言送る
（完了画面にDMの画面例と文面例を載せている。申込内容のコピーも貼れる）
   ↓
運営者がDMで日程・コート・移動費・お支払い方法を案内して確定
   ↓
運営者が自分のカレンダーに手動で登録する
```

### 保存とメールの扱い

- **両方成功** … 完了画面を表示
- **片方だけ成功** … 完了画面は表示し、画面に「確認メールをお送りできませんでした」などの注意書きを出す
- **両方失敗** … **完了画面は出しません。**「もう一度お試しください。繰り返し失敗する場合はInstagramのDMから直接ご連絡ください」と案内します

お客さんがDMを送らずに離脱することもあります。**メールが届いているかどうかを必ず確認してください。**

### 注意

- **移動費の金額はサイトに一切表示していません。** 内容を確認のうえ、DMでご案内してください
- LINE公式を使い始めるときは `apply.html` の完了画面と `index.html` の FLOW、この手順書を書き換えてください

## 6. 申込データの保存先

Supabase の `applications` テーブルです。

- 申込フォームは**公開キーで追加のみ**ができます。読み取り・更新・削除はできません
- 内容を見るときは **Supabase の管理画面**にログインしてください
- 権限の設定は `db/002_rls_insert_only.sql` にあります

### 年齢と「知ったきっかけ」（2026-10-14 追加）

申込フォームの「区分」（12歳未満 / 12〜15歳 …）は廃止し、**年齢を数字で入力**する形にしました。
17歳以下のときだけ「保護者の許可を得ています」のチェックが出ます。
あわせて **「どこで知りましたか?」**（Instagram / TikTok / Facebook / YouTube / 知人の紹介 / その他）を必須で選んでもらいます。

保存先の列：

| 列 | 入る値 |
|---|---|
| `age` | 年齢（数値） |
| `source` | 知ったきっかけ |
| `category` | 「25歳」のような文字列（以前の一覧がそのまま読めるように残しています） |

**`age` と `source` の列は `db/003_age_and_source.sql` を Supabase の SQL Editor で実行して作ってください。**
実行前でも申込は失われません（フォームが自動で質問欄の先頭に `[年齢:25歳 / 知ったきっかけ:Instagram]` と書き足して保存します）が、列として集計できないので早めに実行してください。

メール（EmailJS）のテンプレートでは、`{{category}}` にも年齢が入ります。`{{age}}` `{{source}}` も使えます。

## 7. 料金の設定と表示

料金は **`lib/pricing.js` の1か所**で決まります。トップの MENU、申込フォームの表示・概算・メール本文・保存される金額がすべてここを読みます。

### 2026-10-17 0:00 の自動切り替え

`lib/pricing.js` には旧料金 `OLD` と新料金 `NEW` があり、**2026-10-17 0:00（日本時間）を境に自動で `NEW` に切り替わります**（`SWITCH_AT`）。公開作業は不要です。切り替え後は `OLD` を消して構いません。

| | 旧（10/16まで） | 新（10/17から） |
|---|---|---|
| オンライン 3回 | 2,400円（800/回） | 3,300円（1,100/回） |
| オンライン 5回 | 3,750円（750/回） | 4,900円（980/回） |
| オンライン 10回 | 6,500円（650/回） | 8,900円（890/回） |
| 対面 1人 | 16,500円 | 16,500円 |
| 対面 2人以上 | 16,500円（一律） | 合計22,000円（2人なら1人11,000円） |

### 料金を変えるとき

`NEW` の数字を書き換えて push するだけです。`per`（1回あたり）は表示用なので `price ÷ 回数` を手で入れてください。
対面を一律に戻すなら `lesson: { solo: 16500, group: null }` にします。

### 表示のされ方（新料金・3人の例）

```
対面レッスン 120分(3人 合計)   ¥22,000
1人あたり                     約1人7,334円
練習ボールレンタル 1カゴ       ¥1,200   ← 「あり」のときだけ
移動費(お1人分)               別途
────────────────────────
合計(移動費別)                ¥23,200
```

**移動費の金額は、お客さん向けの画面・メール・DM用の本文のどこにも出していません。**
オンライン動画添削には移動費の表記を出しません。

## 9. セキュリティの前提（2026-10-22 点検）

このサイトは **静的ファイルだけ** を Vercel に置いています。サーバー側で動くコード（Node の API や PHP）はありません。

- **PHP** … 一切使っていない。2026-10-21 の PHP の緊急修正（CVE-2026-109618 / 109619）は無関係
- **Node.js** … 本番では動かない。手元で `npm test` を走らせるだけ。外部パッケージも入れていない（`node_modules` なし）
  - 手元の Node は 2026-10-21 の修正版 **24.22.1** に更新済み（`scoop update nodejs-lts`）
- **外部スクリプト** … EmailJS だけ。バージョンを `4.4.1` に固定し、`integrity`（改ざん検知）を付けた。
  差し替えるときは `tests/booking-hours.test.mjs` が「固定＋integrity」を要求するので、ハッシュを計算し直すこと
- **レスポンスヘッダー** … Cloudflare Pages は `_headers`、Vercel は `vercel.json` で HSTS / nosniff / フレーム埋め込み禁止 などを付けている（内容は同じ）
- **Supabase** … 公開キーは「追加のみ」の想定。`db/002_rls_insert_only.sql` を実行していないと申込が保存されない（メールは届く）。
  公開キーで一覧を読めない状態であることは 2026-10-22 に確認済み（空の配列が返る）

定期的にやること: 月1回 `scoop update nodejs-lts`、EmailJS の新バージョンが出たら差し替え。

## 10. 検索で見つかるようにするための設定（2026-10-26）

- 各ページに日本語のタイトル・説明文・OGP（SNSに貼ったときの画像と文）・canonical を入れてある。OGP画像は `assets/og.png`
- トップには構造化データ（屋号「ダッフィーテニス」、コーチ「渡辺 大輝／ダッフィー先生」、Instagram）を入れてある
- `robots.txt` と `sitemap.xml` を置いてある

**Search Console の状態（2026-10-26 設定済み）**

- プロパティ `https://duffy-tennis.pages.dev/` を追加し、HTMLタグで所有権確認済み（タグは3ページの `<head>` に入っている。消さないこと）
- `sitemap.xml` 送信済み
- トップページの「インデックス登録をリクエスト」は、その日の割り当てを使い切っていたため未実行。急ぐなら翌日以降に URL検査 → 「インデックス登録をリクエスト」を押す（サイトマップがあるので押さなくても数日で拾われる）

これで数日〜2週間ほどで「ダッフィーテニス」で出るようになります。Instagram のプロフィール欄のリンクも `https://duffy-tennis.pages.dev/` に変えてください（検索の評価にも効きます）。

## 11. オンライン動画添削のお支払い（Stripe）

オンライン動画添削だけ、サイト上でお支払いまで完了します（2026-10-29 導入）。対面レッスンは移動費が変わるので今まで通り DM で確定します。

### 流れ

```
申込フォームでオンラインを選んで送信
   ↓
完了画面に「STEP 1 お支払い」→「Stripeで支払う」ボタン（確認メールにも同じリンク）
   ↓
Stripe の決済ページ（メールアドレスは入力済み。氏名・カード番号を入力）
   ↓
支払い完了 → Stripe から領収書メール（お客さん）と入金通知（あなた）
   ↓
お客さんが DM で一言 → 動画の送り方を案内して添削スタート
```

### 設定ファイル

`lib/payments.js` の1か所です。チケット回数ごとに Stripe の支払いリンクを書いてあります。

| | いま（テスト） |
|---|---|
| `mode` | `'test'`（完了画面に「テスト運用中」の注記が出る。本物のカードは使えない） |
| 3回 3,300円 | `https://buy.stripe.com/test_…02` |
| 5回 4,900円 | `https://buy.stripe.com/test_…01` |
| 10回 8,900円 | `https://buy.stripe.com/test_…00` |

### 本番に切り替える手順（1回だけ）

1. Stripe ダッシュボードで **本番環境を有効化**（本人確認・事業内容・入金口座の登録。あなたにしかできません）
2. 本番環境で「商品カタログ」から同じ3商品を作り、それぞれ **支払いリンク** を作る（「顧客の氏名を収集」をオン）
3. 本番環境の 設定 → ビジネス → 送信メール で、言語を日本語、「決済成功時」の領収書をオン
4. `lib/payments.js` の3つの URL を `buy.stripe.com/…`（`test_` なし）に差し替え、`mode: 'live'` にする
5. `npm run deploy`

テストでは「本番モードなのに test_ のリンクが残っている」と失敗するので、差し替え忘れに気づけます。

### イベントの支払い

Stripe で支払いリンクを1本作り、`lib/payments.js` の `events` に足すか、DM・Instagram にそのまま貼ってください。
人数制限は支払いリンクの「決済回数の上限を設定」で付けられます。

### 手数料の目安

国内発行カードは決済額の **3.6%**。8,900円なら約320円、3,300円なら約119円。入金は週1回など Stripe の設定に従います。
